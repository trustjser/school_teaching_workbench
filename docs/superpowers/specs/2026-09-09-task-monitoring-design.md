# 教务端任务处理看板与评分备注设计

## 背景

教务端已经可以创建并下发任务，班级端也能按学生维护状态记录，但教务端目前只能看到任务完成率汇总，无法像考勤大屏一样持续观察全局处理进度，也不能从全局快速进入某个班级的学生明细。任务的评分和备注配置已经存在于任务模型，但任务矩阵没有对应的编辑入口。

## 目标

1. 教务端提供任务全局看板，按任务展示全校、年级、班级的处理进度，并支持进入指定班级的学生明细。
2. 任务详情支持状态、评分、备注的统一编辑；评分和备注仅在任务开启对应能力时出现。
3. 班级端更新后，教务端已打开的看板和详情能自动刷新。
4. 兼容已经下发和已经接收的旧任务，不要求重新创建任务。

## 交互设计

### 任务全局看板

在教务端新增“任务看板”入口，页面顶部提供任务、学年、年级、班级筛选。每个任务卡片展示标题、下发时间、截止时间、参与人数、已完成数、处理中数、待处理数、完成率和平均分。卡片下方展示班级进度列表，按完成率升序排列，显示班级名称、设备在线状态、已完成/总人数和进度条。

点击任务卡片或班级进度行进入任务详情，并携带任务 ID 与班级名称。全局看板保留返回按钮，浏览器刷新后仍能通过 URL 参数恢复选中任务和班级。

### 任务详情

详情页顶部显示任务配置（状态节点、是否评分、是否备注）和班级处理摘要。主体复用现有任务矩阵的网格/表格布局，但学生范围限定为当前班级。点击学生单元格打开编辑面板：

- 状态选择始终展示；
- `scoreEnabled=true` 时显示 0–100 整数输入；
- `noteEnabled=true` 时显示最多 500 字备注输入；
- 保存按钮一次提交状态、评分、备注，沿用 `task_record_upsert` 的本地优先与同步队列；
- 不启用评分或备注时，不渲染对应输入，也不修改已有值。

## 数据与接口

### 全局聚合

扩展任务完成统计查询，返回 `taskId`、`title`、`className`、`grade`、`total`、`finalCount`、`completionRate`、`avgScore`。新增按任务和班级聚合的行，返回班级设备 ID、设备名称、在线状态、总人数、完成数、处理中数、待处理数、完成率、平均分和最后更新时间。

统计以 `task_records` 为事实表，以 `task_status_nodes.is_final=1` 判断完成；平均分只计算非空评分。查询排除软删除学生、任务、记录，并通过 `class_id` 优先、`class_name` 回退匹配班级。

### 班级明细

新增任务班级明细查询，输入 `taskId`、`className`，返回任务、状态节点、学生和记录。结果结构与现有 `task_matrix_query` 兼容，学生只返回当前班级且排除转出学生。

### 同步与刷新

班级端接收广播时同步生成的 `custom_task`、`task_node` 和 `task_record`。对旧广播任务，在班级端更新记录前补发任务和节点快照。教务端 `ingest` 合并任务实体后发出 `TASK_UPDATED`，前端收到事件时刷新任务看板数据和当前详情。

## 组件边界

- `TaskDashboard`：任务与班级聚合卡片、筛选、钻取导航。
- `TaskDetail`：详情摘要、班级上下文和矩阵容器。
- `TaskRecordEditor`：状态、评分、备注编辑面板，只负责表单与保存回调。
- `useTaskStore`：加载聚合、明细，维护当前任务/班级和记录更新。
- Rust `task_cmd`：聚合与明细命令，统一返回前端字段。

## 错误处理

- 查询失败保留页面并显示可重试提示，不清空已有数据。
- 记录保存失败回滚乐观更新，保留用户输入并提示错误。
- 评分越界、备注超过 500 字由后端校验，前端同步显示字段错误。
- 对端离线时记录本地保存成功，状态标记为待同步，继续显示在看板中。

## 验证

- Rust 单元测试覆盖统计字段序列化、任务/班级聚合、评分平均值和任务明细过滤。
- 前端类型检查覆盖新增查询与编辑模型。
- 手动联调：教务端下发任务 → 班级端接收 → 班级端修改状态/评分/备注 → 教务端看板和班级详情自动更新。
