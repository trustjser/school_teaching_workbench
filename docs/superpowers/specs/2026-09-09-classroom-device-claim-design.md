# 教室认领与初始化流程重构设计

## 目标

把“教室”设为唯一业务绑定对象：教务端维护教室及当前学年班级，班级端初始化时用本机不可变设备 ID 认领一个教室。设备表继续作为局域网同步节点的技术目录，但不再作为教务业务配置对象。

## 规则

- 一个有效教室最多绑定一个设备 ID。
- 一个设备 ID最多绑定一个有效教室。
- 同一物理教室可在不同学年绑定不同班级，保留现有 `classroom_assignments` 学年维度。
- 教务端负责创建、修改、删除教室和维护教室-班级关系，不显示设备绑定下拉框。
- 班级端初始化只选择教务端已配置好的教室；班级、年级和学年由教室关系自动带出。
- 班级端不能在设置页换绑；只能通过“重置本机配置”回到初始化向导。重置前在线解除认领，离线则保留待同步操作。
- 教务端不提供重置配置，也不允许运行中切换端类型。

## 数据与接口

保留 `devices`、`classrooms.device_id` 和 `classroom_assignments`。为 `classrooms.device_id` 增加/确认有效记录唯一索引，并在命令层禁止班级端调用教室 CRUD。

新增教务端授权的认领与解除认领接口。认领必须在一个事务中检查教室存在、当前学年有班级绑定、设备没有占用其他教室，以及目标教室为空或已由本设备占用；冲突返回可解释错误。认领成功后同步本机班级配置并触发学生名单同步。

## 页面

教务端教室卡片移除“绑定设备”选择器，展示只读绑定状态、设备短 ID和在线状态。班级端向导展示教室搜索选择器，选项包含教室与当前班级，提交认领后完成初始化。设置页仅保留目录刷新、密钥和班级端重置；教务端隐藏模式切换。

## 兼容与迁移

不删除历史设备记录，不清除已有教室绑定。旧班级端的 `device_name`、`class_id` 等配置在启动时可读取，但新向导不再要求用户维护设备名或重复选择班级。已有绑定继续通过 `classrooms.device_id` 生效。

## 验收

空班级端能拉取教务端已绑定班级的教室并成功认领；同一教室被第二台设备认领时失败；同一设备认领第二间教室时失败；刷新/重启后班级端仍显示认领教室；班级端重置后回到向导且教务端数据不被删除；教务端没有重置配置或模式切换入口。
