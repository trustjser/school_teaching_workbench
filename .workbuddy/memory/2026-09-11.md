# 教务端「切换学年」设计方案（已冻结，待评审）
范围决策：**仅教务端本地**，不广播给班级端（班级端保持独立绑定 client_switch_binding）。
现状：master 已有 `useDirectoryStore.selectedSchoolYearId` + `selectSchoolYear`，但仅内存态、刷新即丢，控件藏在 GradeClassManage 内，无全局明确切换入口；缺对称于班级端 client_switch_binding 的那半。
分层改动（未实现）：
1. 新增 `app_settings.current_school_year_id`（master 专有键，复用 settings_repo::set_raw，零迁移）。
2. 后端 `master_set_current_year` 命令（Master 专属）：校验目标学年存在且 deleted_at IS NULL（仿 client_switch_binding 校验），set_raw 持久化 + 发 SCHOOL_YEAR_CHANGED。
3. 前端 store：loadSchoolYears 初始化优先级改为 app_settings.current_school_year_id → 首个有效学年；新增 switchSchoolYear(id) 置内存态+调命令持久化+联动 loadClasses；当前年失效回退首个有效年并持久化。Settings 类型补 currentSchoolYearId?。
4. 全局控件：TopBar（仅 appTarget==='master'）加「学年：<下拉>」，GradeClassManage 原下拉复用同一 store；useBootstrap 在 applySettings 后 loadSchoolYears() 预热。**切换当前学年必须手动触发，并经二次确认弹窗**（防误切导致视图/筛选整体切换）。
5. 换届**不**自动联动：换届后教务端停留在原当前学年，新学年仅出现在下拉中供用户手动选择；handleRolloverDone 不再调用 switchSchoolYear/selectSchoolYear。
验证：命令单测（非法/已删学年被拒）；手动切年刷新不丢、换届后不自动切（新学年可选）、删当前年回退。
