# 2026-09-07

## 修复：Tauri v2 命令参数契约不匹配（切换菜单成片报 missing required key args）

**根因**：Tauri v2 的 `#[tauri::command]` 按**参数名**去 invoke payload 顶层取 key（key = 参数名转 lowerCamelCase）。
依据：`tauri-2.11.5/src/ipc/command.rs` 的 `CommandItem::deserialize_json` → `v.get(key)`；
`tauri-macros-2.6.3/src/command/wrapper.rs` → key 默认 `to_lower_camel_case()`（默认即 camelCase，无需 `rename_all`）。
所以 Rust 写 `args: XxxArgs` 就要求前端传 `{ args: {...} }`。

**本项目既有约定（重要）**：`invokeCmd` 传的是**扁平 camelCase**，契约以 `docs/01-architecture.md` 命令表和
`src/lib/tauri.ts` 头部注释为准。以后新增命令必须写成扁平参数，不要再用 `args: XxxArgs` 包裹。
实体整体传参的命令（`student_upsert(student)`、`task_upsert(task)` 等）保持 `{ student }` / `{ task }` 形式。

**改动**：`src-tauri/src/commands/` 8 个文件 30 个命令的 `args: XxxArgs` 展开为扁平参数；
删除 25 个无引用 Args 结构体及随之无用的 `use serde::Deserialize;`。
特例：`checkin_mark` 的业务字段也叫 `state`，与 `State<'_, Arc<AppState>>` 冲突 → 托管参数改名 `app_state`
（安全：`CommandArg` 按类型实现，与参数名无关）。
`CheckinMarkArgs` 保留，作为 `checkin_batch_mark(items)` 的元素类型。

**验证**：`cargo check` 0 error 0 warning；本地 `./node_modules/.bin/tsc --noEmit`（v5.9.3）0 error。
42 个命令全部注册且与前端对账一致。

**坑**：`npx tsc` 会拉到非本地版本的 tsc，误报 `Cannot find module '@tauri-apps/api/core'`；
必须用 `./node_modules/.bin/tsc`。

**遗留（未修，均非本次引入）**
- P0 `broadcast_send`：前端传 `targets: { targetType, values }`，Rust 收 `Vec<String>` → 运行时反序列化失败。
- P1 `SendReport`：Rust 返 `{total, queued, failed, targets}`，前端 `src/types/broadcast.ts` 期望 `{expectCount, enqueued, skipped}`。
- P2 前端多传被忽略：`student_list.includeDeleted`（Rust 硬编码 false）、`checkin_mark.note`、`settings_complete_setup.schoolName`。

## 后续修复：B1 broadcast_send 目标契约 + B2 SendReport 字段

**用户决策**：目标选择器展开放在**前端**，Rust 保持只收 device_id 数组。

- `src/types/broadcast.ts` 新增 `resolveTargetDeviceIds(selector, devices)`：
  school→除本端外全部；grade→匹配 `txtGrade`；class→匹配 `txtClassName`；device→匹配 `deviceId`（顺带剔除过期 ID）。
- `db.broadcastSend(id, targetDeviceIds: string[])`；store `send` 同改；`BroadcastCenter.handleCreate`
  先展开再创建，展开为空则 warning toast 并中止。
- Rust `SendReport` 字段改名对齐前端：`total→expect_count`、`queued→enqueued`、`failed→skipped`（camelCase 后即 expectCount/enqueued/skipped）。
- 同步更新契约注释：`src/lib/tauri.ts:31` 与 `docs/01-architecture.md:768` 标注 `targets: deviceId[]`。

**约定（新增）**：凡「UI 选择器 → Rust 只认 ID 列表」的场景，展开一律在前端做，Rust 不解析业务选择器。

**验证**：`cargo check` 0 error 0 warning；`./node_modules/.bin/tsc --noEmit` 0 error。

## 后续修复：B3 Partial&lt;T&gt; 缺字段 + B4 三个被忽略字段

**B3**：前端对 5 个整结构体命令传 `Partial<T>`（新建时 `id/createdAt/syncState/source` 都没有），
Rust 会报 `missing field id`。修法：给 `Student / CustomTask / TaskStatusNode / TaskRecord / BroadcastTask`
加 `Default` derive + 结构体级 `#[serde(default)]`（缺字段取默认值，由 repo 层补全）。
配套在 repo 补空值归一化：`task_repo::upsert` 的 `source` 空→"local"，`student_repo::upsert` 的 `status` 空→"active"。

**B4**：补齐三个前端传了但被忽略的字段
- `student_list` 加 `include_deleted: Option<bool>`（不再硬编码 false）
- `checkin_mark` 加 `note: Option<String>`；`CheckinMarkArgs` 同步加 `note`（批量标记也带上）
- `settings_complete_setup` 加 `school_name: Option<String>`，写入 `school_name` 键
  （前端 `toRuntimeSettings` 读它，之前恒为空 → TopBar 一直显示"未命名学校"）

**验证**：`cargo check` 0 error 0 warning；`tsc --noEmit` 0 error；42/42 命令参数对账**零残留差异**。
契约注释已同步 `src/lib/tauri.ts`（第 3/6/11/21 行）与 `docs/01-architecture.md`（750/753/758/768 行）。

**约定（新增）**：前端对整结构体命令传 `Partial<T>` 是既定用法，Rust 侧实体必须开启 `serde(default)`，
并把「业务默认值」的兜底放在 repo 层（而不是命令层）。

## 打通首次运行配置向导（SetupWizard）接入

**背景**：切换左侧菜单报错的根因修复后，用户想「现在就打通首次配置」——把占位 `SetupScreen` 换成真正可用的向导。

**新增** `src/components/setup/SetupWizard.tsx`：
- 收集 运行模式(client/master)、设备名(必填)、学校名、年级/班级(班级端二选一必填)、共享密钥(base64 32字节，可随机生成)。
- 提交：`settingsCompleteSetup({ mode, deviceName, grade, className, schoolName, secret })` →
  `settingsGetAll()` 取 raw → `applySettings(raw)` → `setPhase('ready')` → navigate 到对应首页。
- 校验：`canSubmit = 设备名非空 && (master 或 年级/班级至少一填) && 密钥合法(留空可)`。

**关键隐藏 bug 已修**（在前序步）：Rust 把「已完成」写入 `completed_setup`，但 `toRuntimeSettings`
原只读 `first_run_done` → 完成配置后刷新会循环回向导。现改为读 `map.completed_setup`（兼容 `first_run_done`）。
`applySettings` 经 `toRuntimeSettings` 把该键映射成 `settings.firstRunDone`，`useBootstrap` 据此决定 `need-setup`/`ready`。

**接线**：`src/router/index.tsx`
- 删除占位 `SetupScreen` 函数及其专属导入（`useNavigate`、4 个 store import）；
- `AppRoot` 门禁 `phase==='need-setup'` 改为渲染 `<SetupWizard />`；
- `SetupWizard` 已在文件顶部导入。

**验证**：`./node_modules/.bin/tsc --noEmit` 0 error（修了一个 `Button size="sm"` 非法的类型错，改 `size="md"`）；
`cargo check` 0 error 0 warning。

**约定（新增）**：首次配置的「完成」判定统一以 Rust 写入的 `completed_setup`=true 为准，前端不自行臆造 first-run 标志。
