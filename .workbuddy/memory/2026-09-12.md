# 2026-09-12

导出「fs.write_file not allowed」修复（commit 93082b8）：
- 根因：src-tauri/capabilities/default.json 只授 `fs:default`（只读基线），而 saveBinary（packages/shared/src/lib/download.ts）走 @tauri-apps/plugin-fs `writeFile(用户另存为路径)`，无 write-file 授权。波及**所有**前端导出（名册/考勤/报表/换届模板），模板下载首次触发暴露。
- 修复：capabilities 增加 `{identifier: "fs:allow-write-file", allow: [$DOWNLOAD/**, $DOCUMENT/**, $DESKTOP/**, $HOME/**]}`；双端共用该 capabilities（各 tauri.*.conf.json 无 capabilities 覆盖）。cargo check 验证 tauri-build 接受该权限标识。
- 注意：capabilities 是构建期烘焙的，`tauri dev` 需重启才生效。
- 教训：Tauri v2 插件能力默认最小化；新增任何插件命令调用前先核对 capabilities 授权（dialog:default 已有所以 save 对话框正常，fs 写却缺）。
