## 修复 CI：`cargo fmt --manifest-path src-tauri/Cargo.toml -- --check` 报错

**根因**：非版本冲突，而是 src-tauri 的 Rust 代码**从未跑过 rustfmt**。全仓 20 个文件、119 处 diff，清一色是「超 100 列未折行」（默认 max_width=100）+ 少量 import 排序。

**版本对齐结论（重要）**：
- CI 固定用 **Rust 1.77.2**（`.github/workflows/ci.yml` 的 `RUST_TOOLCHAIN` + `dtolnay/rust-toolchain@stable with toolchain 1.77.2`，与 `src-tauri/Cargo.toml` 的 `rust-version = "1.77.2"` 一致）。
- 本机默认是 rustc 1.96.1 / rustfmt **1.9.0**。已 `rustup toolchain install 1.77.2 --profile minimal --component rustfmt` 装上 CI 同款。
- 实测两者对本仓库的**格式化决策完全一致**：`cargo +1.77.2 fmt --check` 与 `cargo fmt --check` 输出逐行相同，唯一差别是 1.9.0 会在 `Diff in <file>` 后多打 ` at line N`。→ 本仓不存在 rustfmt 版本漂移风险，本地用哪个版本格式化都可以。

**执行**：`cargo +1.77.2 fmt --manifest-path src-tauri/Cargo.toml`（按 CI 版本落地）。改动 `20 files changed, 605 insertions(+), 188 deletions(-)`。

**改动性质校验（自创手法，值得复用）**：rustfmt 会新增**行尾逗号**和**闭包体花括号**，所以「去空白比哈希」不能直接判定无语义变化。正确做法是 `tr -d '[:space:],'` 后再逐字符 diff：
```
git show HEAD:$f | tr -d '[:space:],' > /tmp/old.txt
tr -d '[:space:],' < $f > /tmp/new.txt
# 再用 difflib.SequenceMatcher 打 opcodes
```
结果：非空白差异仅两类，均语义等价 —— ① `use` 声明重排（`crate::db::repo::settings_repo` 排到 `crate::db::{...}` 之前；`class_repo` 排到 `classroom_repo` 之前）；② 闭包体加/去花括号（`ok_or_else(|| AppError::...)` → `ok_or_else(|| { AppError::... })`、`.map(|c| (a, b))` → `.map(|c| { (a, b) })`）。**注意：这是 rustfmt 的正常行为，不是 bug，review 时不必惊讶。**

**验证（CI 全绿）**：
- `cargo +1.77.2 fmt --check` ✅ / `cargo fmt --check`（1.9.0）✅
- `cargo check` ✅ 8.4s 零警告
- `cargo clippy --all-targets` ✅ 仅 24 warning（CI 未开 `-D warnings`，通过）
- `cargo test` ✅ **92 passed**（lib 层，11.5s）—— 注意 ci.yml 原注释写「当前无 #[test]」，已过时，本次一并更正
- `npm run typecheck` ✅ / `check:boundaries` ✅ / `check:build-targets` ✅

**改动文件**：
- `src-tauri/src/**` 20 个 .rs（纯格式）
- `package.json`：新增 `fmt` 与 `fmt:check` 两个脚本（与 CI 命令逐字一致），避免以后再靠记忆敲长命令
- `.github/workflows/ci.yml`：仅订正 Cargo test 步骤的过时注释

## 修复 Release 打包失败（run 34746934786，tag 1.0.0 → db7a803）

**现象**：Release workflow 三个 OS（ubuntu-22.04 / windows-latest / macos-latest）**全部**挂在同一个 step「Tauri build (affairs / 教务端)」，失败 step 耗时仅 **10–19 秒**，cargo 缓存 0–4s（冷缓存）。

**排查路径（可复用）**：
1. 日志需鉴权，本机无 gh / token，`api.github.com/.../jobs/{id}/logs` 返回 403「Must have admin rights」。**替代手段**：
   - `GET /repos/{o}/{r}/actions/runs/{id}/jobs` → 逐 job/step 的 conclusion + started_at/completed_at（免费、公开仓库可匿名读）。
   - `GET /repos/{o}/{r}/check-runs/{id}/annotations` → 只给 `Process completed with exit code 1.`。
   - **实测 GitHub 公开仓库的 Actions 原始日志（/logs、/job/{id}/logs、zip 包、/lines）一律 404 或 403，无法匿名获取。**
2. **用耗时定位阶段**是关键手法：`tauri build` 内部顺序 = ① 启动 tauri CLI → ② `cargo metadata`（打印 "Looking up installed tauri packages"）→ ③ `beforeBuildCommand`（= `npm run build:affairs`，本地 tsc 25.8s + vite 32s）→ ④ cargo 编译（本例 5m08s）→ ⑤ 打包 .app/dmg。
   失败 step 只有 10–19s ⇒ **必然发生在 ③ 之前**，直接排除前端与 Rust 编译。
3. 交叉验证：CI workflow 的 **Frontend job 在 CI 里是 success**（`npm ci` + tsc + 双端 vite build 全绿）⇒ 前端在 CI 环境没问题，且 `npm ci` 装的依赖（typescript 5.9.3、rollup 各平台包、@tauri-apps/cli 各平台二进制）都齐全。
4. **最终本地复现定案**：`RUSTUP_TOOLCHAIN=1.77.2 npm run tauri:build:affairs` ⇒ 立刻失败：
   ```
   error: failed to download replaced source registry `crates-io`
   Caused by: failed to parse manifest at `.../idna_adapter-1.2.2/Cargo.toml`
   Caused by: feature `edition2024` is required
     ... not stabilized in this version of Cargo (1.77.2)
   ```

**根因**：CI / release 把工具链钉死在 **Rust 1.77.2**，而 Cargo.lock 的依赖树已经涨到 **MSRV 1.88**：`darling 0.23` / `darling_core` / `darling_macro` / `time 0.3.55` / `time-core 0.1.9` / `time-macros 0.2.32` / `plist 1.10.1` 均声明 `rust-version >= 1.88.0`，且 **40+ 个包是 edition 2024**（光 edition2024 就要求 Cargo ≥ 1.85）。lock 是本地新 cargo（1.96.1）生成的，与钉死的旧工具链脱节。

**权威下限算法（值得复用）**：读 `src-tauri/Cargo.lock` 的 659 个包 → 查 **crates.io 稀疏索引**（`https://index.crates.io/{2}/{ab}/{name}`，路径按名字长度分片：1/2/3 字符有专门前缀规则）拿每个版本的 `rust_version` 字段 → 取最大值。**不要只看本地 `~/.cargo/registry/src/`**，那里只有当前平台用的包，Windows/Linux 专属依赖会漏掉。结论：**659 包全平台最高 MSRV = 1.88.0**。

**修复**（4 处）：
- `.github/workflows/ci.yml`：`RUST_TOOLCHAIN: "1.96.1"`，并把 step 的 `toolchain` 改成 `${{ env.RUST_TOOLCHAIN }}` 收敛单一来源；补注释说明为何不能低于 1.88。
- `.github/workflows/release.yml`：同上（原来两处硬编码 1.77.2）。
- `src-tauri/Cargo.toml`：`rust-version = "1.77.2"` → `"1.88"`，这样过旧工具链会报人话「requires rustc 1.88 or newer」，而不是解析依赖时才抛 `edition2024`。
- 选 1.96.1 的理由：**本机默认工具链就是它，且已在本机完成过 release 编译 + .app 打包**（hmm，见下方验证），CI 与本地同版本可消除 rustfmt/clippy/编译行为差异。
- `cargo +1.96.1 metadata --locked` 通过 ⇒ 改 `rust-version` 不会引起 lock 变动。

**版本判定的一致性（多轮实测）**：rustfmt **1.77.2 / 1.88.0 / 1.9.0(1.96.1) 三版对本仓库格式化决策完全相同**，所以 fmt check 在新旧工具链下都过。
