## UI 全面重设计（现代感 + 交互动画 + 深色/浅色/高对比 + 主题切换）

**背景**：项目此前 Tailwind 开 `darkMode:'class'`、store 有 `theme`/`setTheme`（支持 light/dark/high-contrast），但主题从未落到 DOM、无深色样式，组件大量写死 `bg-white`/`slate-*`，实际只有浅色。

**做法**

2. 主题落地：`src/lib/theme.ts`（applyThemeClass + localStorage 持久化）+ `main.tsx` 首帧前应用并订阅 store.theme；切换挂 `.theme-anim` 平滑过渡。Settings 页主题改用 `ThemeSwitcher` 动画分段控件。
3. 动画层：`src/components/motion/` — PageTransition（路由入场）、Reveal/Stagger（错落/滚动揭示）、ThemeSwitcher（日/月/对比滑动控件）。
4. 外壳现代化：AppShell（玻璃侧栏 + 路由动画 + 点阵底纹）、TopBar（玻璃 sticky + 主题切换器）、SideNav（品牌头 + 渐变激活态 + 图标弹入 + 未读脉冲）、StatusBar 主题化。
5. 微交互：Button 加按压缩放/悬浮阴影；Card 用 `.card-interactive` 悬浮抬升 + 高对比描边；Tabs 激活态修正深色对比。
6. 深色扫荡：脚本把 24 个组件/页面里的 `bg-white`/`slate-[0-9]` 全部替换为语义令牌（保留透明度后缀）。

## 目录功能运行时修复：SQLite `ADD COLUMN IF NOT EXISTS` 不支持

**现象**：`init_db` FATAL：`ALTER TABLE students ADD COLUMN IF NOT EXISTS class_id TEXT;` 报 `near "EXISTS": syntax error`。
**根因**：本项目捆绑 SQLite < 3.35，`ALTER TABLE ... ADD COLUMN` 不支持 `IF NOT EXISTS` 子句（该语法 3.35 才加入）；`CREATE TABLE/INDEX IF NOT EXISTS` 则一直支持。
**修复**：`src-tauri/src/db/mod.rs::run_migrations` 改为对 `ALTER ... ADD COLUMN` 语句做幂等保护——`parse_add_column` 解析表/列/类型并剥离 `IF NOT EXISTS`，`column_exists` 用 `PRAGMA table_info` 查列，存在则跳过、否则执行普通 `ALTER`。`002_directory.sql` 注释同步更正（不再声称需 3.35）。另加 `#[cfg(test)]` 回归测试 `migration_adds_class_id_idempotently`（临时库跑两次 run_migrations，断言 class_id 已加且二次幂等）——`cargo test --lib` 通过。
**结论**：用户旧库此前在 ALTER 处即失败、class_id 从未写入，重跑即可正常加列并重建 pending_queue（旧 CHECK 缺 grade/class）。

## SetupWizard 全屏表单适配小窗 / 修复横向滚动条

**现象**：首次运行配置页在小窗口下出现横向滚动条，且底部按钮展示不全。
**根因**：
1. 外层容器用 `w-screen`（100vw），一旦内容超高出现垂直滚动条，滚动条本身会挤占宽度，导致 `w-screen` 超出可视区域并触发水平滚动条。
2. 卡片 `max-w-xl w-full` 缺 `min-w-0`，内容内禀最小宽度可能撑开卡片。
3. 两列 `grid-cols-2` 在窄窗下太挤，输入框/文本域的内禀宽度（textarea 默认 cols、select 默认宽度）容易溢出。
**修复**：
- `SetupWizard.tsx`：外层容器改为 `min-h-screen w-full items-start justify-center overflow-y-auto`（避免 `w-screen` 与垂直滚动条冲突）；卡片加 `min-w-0`；运行模式卡片改为 `flex-col sm:flex-row`；设备/学校、年级/班级两组输入改为 `grid-cols-1 sm:grid-cols-2`，容器加 `min-w-0`。
- `Input.tsx` 包装器、`Textarea.tsx` 原生 textarea、`Select.tsx` 原生 select 都加 `min-w-0`，消除表单控件的内禀最小宽度撑开父容器。
**验证**：`./node_modules/.bin/tsc --noEmit` 0 error。

## Modal 弹窗标题丢失 / 遮罩覆盖不全修复

**现象**：班级/年级编辑弹窗缺少标题栏与关闭按钮，且遮罩只覆盖主内容区、未覆盖顶栏/底栏（见截图）。
**根因**：`<PageTransition>` 使用 `animate-rise-in` 且 `animation-fill-mode: both`，动画结束后元素仍保留 `transform: translateY(0)`。CSS 中任何非 none 的 `transform` 都会为其**固定定位后代**创建新的包含块，导致 `Modal` 的 `position: fixed inset-0` 不再相对于视口，而是相对于 `PageTransition` div；进而被 `main` 的 `overflow-y-auto` 裁剪，标题栏被挤出可视区。
**修复**：
- `src/components/ui/Modal.tsx`：改用 `createPortal(..., document.body)`，把弹窗 DOM 挂到 body 下，彻底脱离 `PageTransition` 的 transform 包含块；面板加 `min-w-0`，标题 `h2` 加 `block w-full` 确保渲染。
- `src/pages/GradeClassManage.tsx`：年级/班级编辑弹窗改用 `widthClass="max-w-lg"`，两列表单网格改为 `grid-cols-1 sm:grid-cols-2`。
**验证**：`./node_modules/.bin/tsc --noEmit` 0 error。
**后续约束**：所有全屏遮罩/固定定位组件都应考虑用 Portal 挂载到 body；页面入场动画若用 transform，其后代不能放 fixed 元素。

## 修复：每次启动都进入「首次运行配置」

**结论（已实证，推翻初判）**：真正根因是 **SQLite WAL 模式未落盘**，与双键无关。
- 实测 `~/Library/Application Support/cn.yipaike.lanworkbench/lan_workbench.db`：主库文件仅 **4096 字节**（空），而 `-wal` 文件 **1.1 MB**，所有写入（含 `completed_setup=true`、`device_name`）都堆在 `-wal`。执行 `PRAGMA wal_checkpoint(TRUNCATE)` 后主库涨到 ~319KB、`-wal` 归零，`completed_setup=true` 才真正落入主库。
- 机制：`db/mod.rs` 连接选项用 `journal_mode(Wal)`；WAL 自动 checkpoint 阈值为 1000 页（约 4MB），`-wal` 1.1MB 未达阈值，且连接池进程退出时未触发 checkpoint → 重启后主库读不到完成标志 → 每次进引导。用户重编后仍复现，说明不是旧二进制读旧键的问题（DB 里 `completed_setup` 早就是 `true`）。

**修复（源码）**：嵌入式单写者场景 WAL 收益极小，改为 `journal_mode(Delete)`（回滚日志），每次提交直接写主库文件，天然跨重启持久。改动见 `src-tauri/src/db/mod.rs::connect_options`。
- 附带加固（防御性，非主因）：`settings_complete_setup` 完成时也翻转 `first_run_done='true'`、`ensure_defaults` 补播种 `first_run_done`，保证任何读旧键的路径一致。

**验证步骤**：`cargo check` 通过；用户需 `npm run tauri dev` 重编（首连会把 DB 从 WAL 切到 DELETE 并清掉 -wal）。重编前我已手动对当前 DB 做一次 `wal_checkpoint(TRUNCATE)`，故即时症状已消失，但必须重编才能根治全部数据的跨重启持久性。
