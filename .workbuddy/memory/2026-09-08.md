## 目录功能运行时修复：SQLite `ADD COLUMN IF NOT EXISTS` 不支持

**现象**：`init_db` FATAL：`ALTER TABLE students ADD COLUMN IF NOT EXISTS class_id TEXT;` 报 `near "EXISTS": syntax error`。
**根因**：本项目捆绑 SQLite < 3.35，`ALTER TABLE ... ADD COLUMN` 不支持 `IF NOT EXISTS` 子句（该语法 3.35 才加入）；`CREATE TABLE/INDEX IF NOT EXISTS` 则一直支持。
**修复**：`src-tauri/src/db/mod.rs::run_migrations` 改为对 `ALTER ... ADD COLUMN` 语句做幂等保护——`parse_add_column` 解析表/列/类型并剥离 `IF NOT EXISTS`，`column_exists` 用 `PRAGMA table_info` 查列，存在则跳过、否则执行普通 `ALTER`。`002_directory.sql` 注释同步更正（不再声称需 3.35）。另加 `#[cfg(test)]` 回归测试 `migration_adds_class_id_idempotently`（临时库跑两次 run_migrations，断言 class_id 已加且二次幂等）——`cargo test --lib` 通过。
**结论**：用户旧库此前在 ALTER 处即失败、class_id 从未写入，重跑即可正常加列并重建 pending_queue（旧 CHECK 缺 grade/class）。

## Modal 弹窗标题丢失 / 遮罩覆盖不全修复

**现象**：班级/年级编辑弹窗缺少标题栏与关闭按钮，且遮罩只覆盖主内容区、未覆盖顶栏/底栏（见截图）。
**根因**：`<PageTransition>` 使用 `animate-rise-in` 且 `animation-fill-mode: both`，动画结束后元素仍保留 `transform: translateY(0)`。CSS 中任何非 none 的 `transform` 都会为其**固定定位后代**创建新的包含块，导致 `Modal` 的 `position: fixed inset-0` 不再相对于视口，而是相对于 `PageTransition` div；进而被 `main` 的 `overflow-y-auto` 裁剪，标题栏被挤出可视区。
**修复**：
- `src/components/ui/Modal.tsx`：改用 `createPortal(..., document.body)`，把弹窗 DOM 挂到 body 下，彻底脱离 `PageTransition` 的 transform 包含块；面板加 `min-w-0`，标题 `h2` 加 `block w-full` 确保渲染。
- `src/pages/GradeClassManage.tsx`：年级/班级编辑弹窗改用 `widthClass="max-w-lg"`，两列表单网格改为 `grid-cols-1 sm:grid-cols-2`。
**验证**：`./node_modules/.bin/tsc --noEmit` 0 error。
**后续约束**：所有全屏遮罩/固定定位组件都应考虑用 Portal 挂载到 body；页面入场动画若用 transform，其后代不能放 fixed 元素。

## 修复：每次启动都进入「首次运行配置」

**真正的根因（最终定位，推翻前两轮判断）**：**前端 `useBootstrap` 读取的是过期的 Zustand state 引用**，与数据库完全无关。
- 第 30 行 `const app = useAppStore.getState()` 捕获了启动前的 state 引用；第 35 行 `app.applySettings(settings)` 内部 `set()` 会**生成新的 state 对象**（Zustand 浅合并 `Object.assign({}, state, next)`），但 `app` 仍指向旧对象；第 37 行 `app.settings.firstRunDone` 读到的永远是旧 `settings` 默认值 `false` → 每次都 `setPhase('need-setup')`。
- 这解释了为何 DB 里一直有 `completed_setup=true`、重编也无效：读取逻辑根本没用到新值。完成配置后能「进去」是因为 SetupWizard 走的是组件内的 `useAppStore` hook（实时引用），正常生效；重启时 `useBootstrap` 用的是陈旧引用才出错。
- 修复：第 37 行改为 `useAppStore.getState().settings.firstRunDone`。`tsc --noEmit` 通过。

**次要但真实的问题（已一并修）**：SQLite 跑在 WAL 模式，写入只堆在 `-wal`（实测主库仅 4KB、`-wal` 1.1MB，未达 1000 页自动 checkpoint 阈值，进程退出也未触发落盘），导致全部数据跨重启不持久。`db/mod.rs::connect_options` 的 `journal_mode(Wal)` 改为 `Delete`（回滚日志，提交直写主库），`cargo check` 通过。这是正确性加固，但**不是「每次进引导」的直接原因**——直接原因是上面的 stale-state 读取。

**历史误判归档**：① 曾误判为 `first_run_done`/`completed_setup` 双键不一致（实际 DB 里 completed_setup 早已是 true，且前端优先读它）；② 曾误判为 WAL 未落盘是唯一原因（WAL 确实是问题，但不改前端仍会每次进引导）。两个方向的修复都保留：双键翻转（防御性）+ WAL→DELETE（持久性）+ stale-state 读取修正（根因）。

**用户侧动作**：`npm run tauri dev` 重编即可。重编前我曾手动对 DB 执行 `wal_checkpoint(TRUNCATE)`，故即时症状已消失；重编后三处修复共同保证不再复现。

## 修复：年级/班级弹窗输入框只能输入一个字符就失焦

**现象**：`GradeClassManage` 的年级弹窗、班级弹窗输入框，输一个字就失焦，无法连续输入。
**根因**：`src/components/ui/Modal.tsx` 的 `useEffect`（锁 body 滚动 + 开时 `setTimeout(()=>panel.focus(),30)`）依赖项写成了 `[open, onClose]`。但调用方一律传 `onClose={() => setGradeDraft(null)}` 这种**每次渲染都是新函数**的闭包；每次按键 `setState` 触发父组件重渲染 → `onClose` 引用变 → effect 反复重跑 → 又调度一次 30ms 后 `panel.focus()`，把焦点从输入框抢回面板。这就是「输一个字就失焦」。
**修复**：
- `Modal.tsx`：`onClose` 改经 `onCloseRef` 持有最新值，effect 依赖收敛为 `[open]`（只在开关时跑一次）。`panel.focus()` 仅开弹窗时执行一次，按键不再触发。
- `Drawer.tsx`：同一 `[open,onClose]` 反模式（它无 focus 偷窃，仅每次渲染重挂 keydown 监听造成抖动），一并改用 `onCloseRef` + 依赖 `[open]`，与 Modal 对齐，顺带给 `StudentEditDrawer` 等消除监听器抖动。
**验证**：`./node_modules/.bin/tsc --noEmit` 0 error。
**通用约束（新增）**：凡 `useEffect` 用到父组件传来的回调（onClose 之类），一律用 ref 持有最新值，依赖只列「真正触发条件」（如 `[open]`），不要把它写进依赖数组——否则父组件每次渲染传入新函数会让 effect 反复执行。

## 修复：考勤大屏 / 全校总览错误展示（undefined/NaN）

**现象**：截图中 `全校出勤率` 次级文本显示 `undefined/0 已标记`；`已提交班级` 显示 `undefined/undefined`；`异常学生` 显示 `NaN`；`刷新`按钮无加载反馈。
**根因**：Rust 侧 `SchoolSummary` 与 `ClassAttendanceRow` 的字段命名/缩放比例和前端 TS API 不匹配。
- Rust `SchoolSummary`：`total_classes` / `submitted_classes` / `present_cnt` / `absent_cnt` / `leave_cnt` / `late_cnt` / `attendance_rate`（0–1）；前端 TS 期望 `classCount` / `submittedClassCount` / `present` / `absent` / `leave` / `late` / `attendanceRate`（0–100），且缺 `markedStudents` / `conflictCount` / `date`。
- Rust `ClassAttendanceRow`：`total_cnt` / `present_cnt` 等；TS 期望 `total` / `present` 等；`attendance_rate` 同样是 0–1，前端按 0–100 展示。
因此前端读到 `undefined`，`summary.absent + summary.leave` 得到 `NaN`。
**修复**：
- `src-tauri/src/db/models.rs`：`SchoolSummary` / `ClassAttendanceRow` 加 `#[serde(rename)]` 把内部 snake_case 映射到前端 camelCase；新增 `date` / `marked_students` / `conflict_count` 字段。
- `src-tauri/src/commands/checkin_cmd.rs` 与 `src-tauri/src/import_export/export.rs`：同步更新 SQL，新增 `? AS date` / `marked_students` / `conflict_count`，并把 `attendance_rate` 计算式乘以 100，返回 0–100 百分比数字。
- 前端 `MasterHome.tsx` / `AttendanceBoard.tsx`：刷新按钮改用 `loading={loading}` + `RefreshCw` 图标，显示加载状态；汇总数字加 `?? 0` 防御性兜底，避免未来 API 抖动再出现 `undefined/NaN`。
**验证**：`./node_modules/.bin/tsc --noEmit` 0 error；`cargo check` 0 error（macOS 上 cargo 在 `~/.cargo/bin/cargo`，PATH 未覆盖，用绝对路径）。
**通用约束（新增）**：Rust ↔ TS 的结构体返回必须保持字段名与缩放比例一致；涉及百分比时，后端统一按 0–100 数字返回，前端 `formatPercent` / `StatCard` 直接展示，不再各自换算。

## 修复：节点编辑卡色板扁平 + 终态开关未对齐

**现象**：截图反馈节点卡片中「配色」色板圆点被压扁成椭圆；「终态」开关与「节点名称」输入框不在同一水平线上，开关位置偏高。
**根因**：
- 色板按钮只有 `h-7 w-7 rounded-full`，父 flex 容器换行时圆点会被横向挤压变形。
- `Toggle` 组件外框自带 `px-1 py-2` 内边距，且 label 与 switch 左右排列；放在 `items-end` 行内时，内边距把 switch 抬高，导致与 Input 输入框底部不对齐。
**修复**：
- `src/pages/BroadcastCenter.tsx`：`ColorSwatchPicker` 的色板按钮加 `shrink-0 aspect-square box-border`，强制保持正圆并防止被挤压。
- `src/components/ui/Toggle.tsx`：新增可选 `className` prop，并追加到外层 label 的 className 末尾（允许调用方覆盖内边距等样式）。
- `src/pages/BroadcastCenter.tsx`：`NodeEditorCard` 里「终态」改用上方独立 `<span>` 标签 + 无 label 的 `Toggle`，并传 `className="py-0 px-0"` 去掉内边距，使 switch 底部与 Input 输入框底部严格对齐。
**验证**：`./node_modules/.bin/tsc --noEmit` 0 error（`EXIT:0`）。
